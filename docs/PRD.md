## 1. Обзор продукта

**DealForge CRM** — внутренняя CRM-система для малого бизнеса на рынке Узбекистана. Система помогает отделу продаж вести лиды по воронке, контролировать источники заявок, ставить задачи и отслеживать результаты через аналитику.

**Тип продукта:** Single-tenant веб-приложение  
**Целевой рынок:** Узбекистан  
**Целевая команда:** 1–10 человек (менеджеры по продажам + руководство)  
**Языки интерфейса:** Русский, Ўзбекча (Lotin)  
**Валюты:** UZS (основная), USD (параллельная)

## 2. Цели продукта

### Бизнес-цели
- Заменить Excel/мессенджеры единым инструментом управления продажами
- Дать руководителю прозрачность по работе каждого менеджера
- Ускорить цикл сделки за счёт структурированного процесса (воронки)
- Не терять лиды из разных источников (webhook, форма, ручной ввод)

### Метрики успеха (KPI)
- Все лиды фиксируются в системе (0 потерянных заявок)
- Время реакции на новый лид < 30 минут
- Конверсия воронки видна в реальном времени
- Руководитель может оценить эффективность менеджера за любой период

### Out of Scope (не входит в v1)
- Интеграция с Payme/Click (оплата)
- Интеграция с Instagram/Facebook/Telegram как источниками лидов
- Нативное мобильное приложение (iOS/Android)
- Внутренний чат между сотрудниками
- Автоматические сценарии (триггеры/ботоматика)
- Биллинг и подписки (система не SaaS на первом этапе)
- Управление каталогом товаров/услуг

## 4. Функциональные требования

### 4.1 Аутентификация и управление пользователями

#### Аутентификация
- Вход по email + пароль
- JWT (access token + refresh token)
- Хеширование паролей: Argon2
- Выход из системы (invalidate refresh token)
- Смена пароля (старый пароль + новый)

#### Управление пользователями (только Admin)
- Создание пользователя: имя, фамилия, email, username, пароль, роль
- Редактирование профиля пользователя
- Деактивация (soft delete — is_active = false)
- Просмотр списка пользователей с фильтром по роли и статусу

#### Профиль текущего пользователя
- Просмотр и редактирование: имя, фамилия, email, username
- Смена пароля

---

### 4.2 Воронки продаж (Funnels)

#### Воронки
- Создание воронки с названием
- Переименование воронки
- Мягкое удаление воронки (лиды остаются)
- Список воронок с пагинацией и поиском по названию

#### Стадии воронки
Каждая стадия имеет:
- **Название** — отображается на Kanban-доске
- **Вероятность выигрыша** — 0–100% (используется в аналитике)
- **Цвет** — hex-код для визуальной идентификации
- **Тип (kind):** `initial` / `intermediate` / `won` / `lost`
- **Порядок** — drag-and-drop сортировка
- **is_archived** — скрыть стадию без удаления

**Операции:**
- Создание, редактирование, удаление стадии
- Перемещение (reorder) стадий внутри воронки
- Нельзя удалить воронку, если в ней есть активные лиды (показать ошибку)

**Бизнес-правила:**
- В воронке должна быть минимум 1 стадия типа `initial` и 1 типа `won`/`lost`
- Лиды в стадии `won` засчитываются как закрытые сделки в аналитике

### 4.3 Лиды (Leads)

#### Структура лида

| Поле | Тип | Обязательное |
|---|---|:---:|
| Имя | Текст | ✅ |
| Контактный телефон | Телефон (UZ формат: +998XXXXXXXXX) | ❌ |
| Email контакта | Email | ❌ |
| Воронка | Ссылка на Funnel | ✅ |
| Стадия | Ссылка на FunnelStage | ✅ |
| Источник | Ссылка на Source | ❌ |
| Назначен на | Пользователь (Consultant/Manager) | ❌ |
| Приоритет | Enum: cold / warm / hot | ❌ |
| Сумма сделки (UZS) | BigInt | ❌ |
| Сумма сделки (USD) | Decimal | ❌ |
| Комментарий | Многострочный текст | ❌ |
| Кастомные поля | Динамические значения | ❌ |
| Дата создания | Timestamp (авто) | ✅ |
| Дата обновления | Timestamp (авто) | ✅ |

#### Операции с лидами
- **Создание** — вручную (Consultant, Sales Manager, Director, Admin) или через источник автоматически; при ручном создании можно выбрать назначенного менеджера или оставить авто-назначение (round-robin по пулу)
- **Редактирование** — изменение любого поля (с учётом прав)
- **Перемещение по стадиям** — drag-and-drop на Kanban или выбор в форме лида
- **Назначение** — переназначить лид другому менеджеру (Sales Manager+)
- **Архивация** — лид скрывается из активных списков, не удаляется; архивированный лид можно восстановить (Sales Manager+)
- **Мягкое удаление** — окончательное скрытие с пометкой is_deleted (Sales Manager+)
- **Восстановление удалённого** — Sales Manager+

**Правила:**
- Лид находится **только в одной воронке** одновременно (переводится целиком)
- Bulk-операции (массовые действия) не реализуются в v1
- Дублирование лида не реализуется в v1

#### Визуализация лидов

**Kanban-доска (основной вид):**
- Колонки = стадии воронки
- Карточка лида показывает: имя, приоритет (цвет), источник, назначенный менеджер, сумма, дата
- Drag-and-drop для перемещения между стадиями
- Переключение между воронками через вкладки/дропдаун
- Быстрая фильтрация: по менеджеру (Sales Manager+), по приоритету, по источнику, по дате

**Детальная карточка лида (Modal / отдельная страница):**
- Все поля лида
- История действий (timeline)
- Задачи
- Комментарии/заметки

#### История действий (Timeline)
Система автоматически записывает события:
- Создание лида
- Изменение стадии (кем, когда, из какой → в какую)
- Изменение назначения (кем, кому)
- Изменение приоритета
- Добавление комментария (вручную)
- Факт звонка / встречи (вручную — "Позвонил", "Написал", "Встреча")
- Создание / выполнение задачи

Каждое событие: иконка типа, текст, дата/время, автор.

#### Комментарии
- Текстовое поле — добавить комментарий с датой и автором
- Редактирование и удаление своих комментариев (в течение 24ч)
- Список в хронологическом порядке

Задача привязана к лиду.

#### Структура задачи
| Поле | Тип | Обязательное |
|---|---|:---:|
| Название | Текст | ✅ |
| Описание | Многострочный текст | ❌ |
| Дедлайн | Дата + время | ✅ |

#### Операции

- Редактирование задачи (автор или Sales Manager+)
- Изменение статуса
- Удаление задачи (автор или Sales Manager+)

- Просмотр всех своих задач (отдельный виджет / страница)

#### Уведомления о задачах
- In-app уведомление назначенному пользователю при создании задачи
- In-app уведомление при приближении дедлайна (за 1 час)
- In-app уведомление при просроченной задаче (в день дедлайна)

### 4.5 Источники лидов (Sources)

Поддерживаются три типа источников:

#### 4.5.1 Manual (Ручной)
- Менеджер сам создаёт лид и выбирает источник "Ручной ввод"
- Не требует конфигурации

#### 4.5.2 Public Form (Публичная форма)
- Генерируется уникальная публичная ссылка (URL)
- Форма доступна без авторизации
- Конфигурируется:
  - Заголовок формы
  - Список полей (маппинг на поля лида и кастомные поля)
  - Сообщение после отправки ("Спасибо, мы свяжемся с вами")
  - URL для редиректа после отправки (опционально)
  - Стратегия назначения: вручную (фиксированный менеджер) или авто-пул (round-robin по активным менеджерам)
- После отправки формы — автоматическое создание лида в указанной воронке/стадии
- Форма должна работать на мобильных устройствах

#### 4.5.3 Webhook
- Генерируется уникальный endpoint URL
- Генерируется секретный токен (HMAC SHA-256 подпись)
- Возможность регенерации секрета
- Маппинг JSON-полей входящего запроса на поля лида
- Обработка входящего webhook → создание лида
- Логирование входящих запросов (успех/ошибка)

#### Управление источниками
- Список источников с фильтром по типу и активности
- Активация / деактивация источника (деактивированный не создаёт лиды)
- Мягкое удаление
- Поиск по названию

### 4.6 Кастомные поля (Custom Fields)

Администратор/менеджер может создавать дополнительные поля для лидов.

#### Типы полей

| Тип | Описание | Хранение |
|---|---|---|
| `text` | Строка произвольной длины | String |
| `number` | Число (целое или дробное) | Decimal |
| `date` | Дата (без времени) | Date |
| `boolean` | Чекбокс (да/нет) | Boolean |
| `select_one` | Выбор одного значения из списка | Enum ID |
| `select_all` | Выбор нескольких значений | List of Enum IDs |

#### Управление кастомными полями
- Создание поля: название, тип, для `select_*` — список вариантов
- Редактирование названия поля
- Добавление/удаление вариантов для select-полей
- Мягкое удаление (значения лидов сохраняются)
- Восстановление удалённого поля
- Сортировка порядка отображения полей
- Уникальность названия поля в рамках системы

#### Отображение
- Кастомные поля отображаются в детальной карточке лида в секции "Доп. информация"
- Пустые поля отображаются как прочерк (—) или скрываются (настройка)

### 4.7 Аналитика и отчёты

#### 4.7.1 Дашборд (главный экран аналитики)

**Фильтры:**
- Период: сегодня / эта неделя / этот месяц / прошлый месяц / произвольный диапазон
- Воронка: конкретная или все
- Менеджер: конкретный или все (только для Director+)

**Виджеты:**

1. **Сводка** (4 карточки в ряд):
   - Всего новых лидов за период
   - Всего выигранных сделок за период
   - Общая сумма выигранных сделок (UZS + USD)
   - Конверсия (выиграно / создано × 100%)

2. **Воронка — лиды по стадиям** (funnel chart или bar chart):
   - Количество лидов на каждой стадии
   - Процент конверсии между стадиями

3. **Динамика лидов** (line/bar chart):
   - Новые лиды по дням/неделям за период
   - Выигранные лиды по дням/неделям за период

4. **Эффективность менеджеров** (таблица):
   - Столбцы: Менеджер, Новые лиды, Выиграно, Проиграно, Конверсия, Сумма сделок
   - Сортировка по любому столбцу
   - Только для Sales Manager+ (Director видит всех, Manager видит свою команду)

5. **Источники лидов** (pie/donut chart):
   - Распределение лидов по источникам за период

6. **Среднее время в стадии** (bar chart):
   - Среднее количество дней, которое лид проводит в каждой стадии

#### 4.7.2 Экспорт данных

**Экспорт списка лидов (Excel/CSV):**
- Применяются текущие фильтры
- Поля: имя, контакт, воронка, стадия, источник, менеджер, приоритет, сумма, кастомные поля, дата создания
- Формат файла: `.xlsx` (Excel) или `.csv`

**Экспорт отчёта по аналитике (PDF):**
- Период и фильтры
- Все виджеты дашборда в виде статичных графиков
- Подпись даты генерации и имени пользователя

### 4.8 Уведомления (In-App)

Уведомления отображаются в колокольчике (header навигации).

| Событие | Кому |
|---|---|
| Назначен новый лид | Назначенному менеджеру |
| Переназначен лид | Новому назначенному + старому |

**Требования к уведомлениям:**

- Счётчик непрочитанных на иконке
- Хранение последних 100 уведомлений на пользователя

## 5. Нефункциональные требования

### 5.1 Производительность
- Время ответа API: < 300ms для 95% запросов (при нагрузке до 50 RPS)
- Kanban-доска с до 500 лидами загружается < 2 секунд
- Аналитика (агрегация) вычисляется < 3 секунд

### 5.2 Безопасность
- HTTPS обязателен (TLS 1.2+)
- JWT access token: TTL 15 минут, refresh token: TTL 30 дней
- Все API-эндпоинты требуют авторизацию (кроме Public Form и Login)
- Webhook-эндпоинт верифицирует подпись HMAC SHA-256
- SQL-инъекции исключены (ORM + параметризованные запросы)
- Все пароли хешируются Argon2

### 5.3 Доступность и совместимость
- **Браузеры:** Chrome 90+, Firefox 90+, Safari 14+, Edge 90+
- **PWA:** адаптивный дизайн, работает на мобильных устройствах (iOS Safari, Android Chrome)
- **Разрешения:** от 375px (мобильный) до 2560px (широкий монитор)

### 5.4 Масштабируемость
- Система рассчитана на до 10 000 лидов в базе
- При росте нагрузки — горизонтальное масштабирование через Docker

### 5.5 Надёжность
- Uptime: 99% (допустимо ~7ч даунтайма в месяц для single-tenant)
- Бэкап базы данных: ежедневно (автоматический PostgreSQL dump)
- Логирование всех ошибок (server-side)

## 13. Глоссарий

| Термин | Определение |
|---|---|
| **Лид** | Потенциальный клиент, проходящий по воронке продаж |
| **Воронка (Funnel)** | Последовательность стадий, отражающая процесс продажи |
| **Стадия (Stage)** | Шаг внутри воронки (например: "Новый" → "Переговоры" → "Выиграно") |
| **Источник (Source)** | Канал, откуда пришёл лид (форма, webhook, ручной ввод) |
| **Кастомное поле** | Дополнительное поле, созданное пользователем для хранения специфических данных |
| **Timeline** | Хронологическая история всех событий по лиду |
| **Конверсия** | Процент лидов, перешедших с одной стадии на следующую |
| **Приоритет** | Температура лида: cold (холодный), warm (тёплый), hot (горячий) |
| **Single-tenant** | Система развёрнута для одной компании, данные не разделяются между клиентами |
| **PWA** | Progressive Web App — веб-приложение с поддержкой мобильных устройств |
