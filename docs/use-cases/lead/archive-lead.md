# UseCase: ArchiveLead — Архивировать / Разархивировать лид

## Что решает

Переключает флаг `is_archived` у лида. Архивированный лид скрыт из основных представлений (Kanban, таблица), но **можно восстановить** в любой момент. Используется для лидов в финальных стадиях (выиграно/проиграно) или для временного скрытия.

**Статус:** ❌ Не реализовано (планируется — Приоритет 1)

---

## Участники

| Поле | Значение |
|------|----------|
| **Actor** | Пользователь с доступом к лиду |
| **Роли** | `consultant` (только свои), `sales_manager`, `director`, `admin` |

---

## Входные данные

| Поле | Тип | Описание |
|------|-----|----------|
| `lead_id` | `UUID` | ID лида |
| `archive` | `bool` | `True` — архивировать, `False` — разархивировать |

---

## Порядок действий

```
1. Открыть Unit of Work

2. Загрузить лид из БД
   └─ Если не найден → LeadNotFoundError

3. Проверить доступ по роли:
   - Consultant → только свои лиды

4. Если archive = True:
   └─ lead.archive() → is_archived = True
   └─ Создать LeadTimelineEvent "lead_archived"

5. Если archive = False:
   └─ lead.restore() → is_archived = False
   └─ Создать LeadTimelineEvent "lead_restored"

6. Сохранить лид в БД

7. Зафиксировать транзакцию (commit)
```

---

## Возможные ошибки

| Ошибка | Условие |
|--------|---------|
| `LeadNotFoundError` | Лид не найден |
| `LeadAccessDeniedError` | Нет прав на изменение |

---

## Результат

`None` — успешное выполнение.

---

## Бизнес-правила

- `is_archived` — **обратимая** операция (в отличие от `is_deleted`)
- Архивированный лид **не появляется** в Kanban-доске и основном списке
- Архивированный лид **доступен** через фильтр `is_archived = True` в `ListLead`
- Задачи и события timeline архивированного лида сохраняются и доступны при разархивировании
