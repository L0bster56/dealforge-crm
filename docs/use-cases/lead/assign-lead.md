# UseCase: AssignLead — Назначить лид менеджеру

## Что решает

Назначает лид конкретному менеджеру (`assigned_to`). Менеджер получает уведомление о назначении. Фиксируется в timeline. Consultant не может переназначать лиды.

**Статус:** ❌ Не реализовано (планируется — Приоритет 1)

---

## Участники

| Поле | Значение |
|------|----------|
| **Actor** | Менеджер или выше |
| **Роли** | `sales_manager`, `director`, `admin` |

---

## Входные данные

| Поле | Тип | Описание |
|------|-----|----------|
| `lead_id` | `UUID` | ID лида |
| `user_id` | `UUID \| None` | ID назначаемого менеджера (None = снять назначение) |

---

## Порядок действий

```
1. Открыть Unit of Work

2. Загрузить лид из БД
   └─ Если не найден → LeadNotFoundError

3. Проверить права актора:
   - Consultant не может назначать
   → Если нет прав → PermissionError

4. Если user_id передан:
   - Загрузить пользователя по user_id
   - Проверить, что он активен и имеет роль consultant или sales_manager
   └─ Если нет → AssignmentError

5. Сохранить предыдущий assigned_to для записи события

6. Вызвать lead.assign(user_id)
   └─ Обновляет assigned_to

7. Сохранить лид в БД

8. Создать LeadTimelineEvent "assigned" (автоматически)

9. Создать Notification для нового назначенного пользователя (если user_id != None)

10. Зафиксировать транзакцию (commit)
```

---

## Возможные ошибки

| Ошибка | Условие |
|--------|---------|
| `LeadNotFoundError` | Лид не найден |
| `PermissionError` | Consultant пытается назначать лид |
| `AssignmentError` | Назначаемый пользователь неактивен или имеет неподходящую роль |

---

## Результат

`None` — успешное выполнение.

---

## Бизнес-правила

- В пул назначения (`assigned_to`) входят только `consultant` и `sales_manager` — director и admin в него не назначаются
- `user_id = None` снимает назначение — лид становится "без менеджера"
- При смене назначенного менеджера **старый** менеджер теряет доступ (если он `consultant`)
- Уведомление отправляется только **новому** назначенному менеджеру
