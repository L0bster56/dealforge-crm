# UseCase: ListLead — Список лидов

## Что решает

Возвращает постраничный список лидов с фильтрацией. Основной экран CRM — Kanban-доска или таблица лидов. Применяет ролевую фильтрацию: `consultant` видит только свои лиды.

**Статус:** ❌ Не реализовано (планируется — Приоритет 1)

---

## Участники

| Поле | Значение |
|------|----------|
| **Actor** | Любой авторизованный пользователь |
| **Роли** | Все роли (с ограничениями) |

---

## Входные данные

| Поле | Тип | Описание |
|------|-----|----------|
| `funnel_id` | `UUID \| None` | Фильтр по воронке |
| `stage_id` | `UUID \| None` | Фильтр по этапу |
| `assigned_to` | `UUID \| None` | Фильтр по менеджеру |
| `source_id` | `UUID \| None` | Фильтр по источнику |
| `priority` | `Priority \| None` | Фильтр по приоритету |
| `is_archived` | `bool` | Включать архивированные |
| `search` | `str \| None` | Поиск по имени/телефону/email |
| `page` | `int` | Страница |
| `size` | `int` | Размер страницы |

---

## Порядок действий

```
1. Применить ролевой фильтр:
   - Если actor.role == consultant → принудительно добавить фильтр assigned_to = actor.id

2. Открыть Unit of Work

3. Загрузить список лидов через репозиторий с применением всех фильтров

4. Вернуть PageResult[LeadListItemDTO]
```

---

## Возможные ошибки

Нет специфических ошибок.

---

## Результат

`PageResult[LeadListItemDTO]` — краткая информация о лидах (без кастомных значений — они загружаются в `GetLead`).

---

## Бизнес-правила

- Удалённые лиды (`is_deleted = True`) **не отображаются** в обычном списке
- Архивированные лиды (`is_archived = True`) скрыты по умолчанию, отображаются только при `is_archived = True` в фильтре
- **Consultant** не может запросить чужие лиды — фильтр `assigned_to` принудительно перекрывается его собственным ID
