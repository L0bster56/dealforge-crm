# UseCase: DeleteCustomField — Удалить кастомное поле (soft delete)

## Что решает

Мягко удаляет кастомное поле — устанавливает `is_deleted = True`. Поле скрывается из интерфейса добавления значений, но уже сохранённые значения в лидах (`LeadCustomFieldValue`) **сохраняются**. Поле можно восстановить через `RestoreCustomField`.

**Файл:** `backend/src/backend/application/lead/use_cases/custom_fields/delete_custom_field.py`

**Статус:** ✅ Реализовано

---

## Участники

| Поле | Значение |
|------|----------|
| **Actor** | Менеджер или выше |
| **Роли** | `sales_manager`, `director`, `admin` |

---

## Входные данные

Поле передаётся как атрибут use case (`self.field`). Дополнительных параметров нет.

---

## Порядок действий

```
1. Проверить права актора через CanMangeCustomField
   └─ Если нет прав → ошибка PermissionError

2. Открыть Unit of Work

3. Вызвать field.delete()
   └─ Устанавливает is_deleted = True

4. Сохранить через uow.custom_fields.update(field=self.field)

5. Зафиксировать транзакцию (commit)
```

---

## Возможные ошибки

| Ошибка | Условие |
|--------|---------|
| `PermissionError` | Нет прав |

---

## Результат

`None` — успешное выполнение без возвращаемого значения.

---

## Бизнес-правила

- Удаление **мягкое** — `LeadCustomFieldValue` в лидах **не удаляются**
- Удалённое поле **не отображается** в форме лида, но его значения видны в карточке лида (как "удалённое поле")
- Нельзя добавить новые значения к удалённому полю (блокируется на уровне `AddEnumValue`)
- Поле можно использовать в форме `public_form`-источника — при удалении поля форма продолжит работу (значения поступают), но поле не отображается в CRM
