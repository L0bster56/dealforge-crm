# UseCase: AddEnumValue — Добавить вариант выбора в кастомное поле

## Что решает

Добавляет новый вариант выбора (`enum`) в кастомное поле типа `select_one` или `select_all`. Позволяет расширять список доступных значений без пересоздания поля.

**Файл:** `backend/src/backend/application/lead/use_cases/custom_fields/add_enum_value.py`

**Статус:** ✅ Реализовано

---

## Участники

| Поле | Значение |
|------|----------|
| **Actor** | Менеджер или выше |
| **Роли** | `sales_manager`, `director`, `admin` |

---

## Входные данные (`AddEnumValueCommand`)

| Поле | Тип | Описание |
|------|-----|----------|
| `value` | `str` | Новый вариант выбора |

Поле передаётся как атрибут use case (`self.custom_field`).

---

## Порядок действий

```
1. Проверить права актора через CanMangeCustomField
   └─ Если нет прав → ошибка PermissionError

2. Открыть Unit of Work

3. Вызвать custom_field.add_enum(cmd.value)
   └─ Создаётся новый LeadCustomFieldEnum с уникальным UUID
   └─ Добавляется в список field.enums

4. Сохранить через uow.custom_fields.update(self.custom_field)

5. Зафиксировать транзакцию (commit)
```

---

## Возможные ошибки

| Ошибка | Условие |
|--------|---------|
| `PermissionError` | Нет прав |

---

## Результат

`None` — успешное выполнение без возвращаемого значения.

---

## Бизнес-правила

- Уникальность значения **не проверяется** на уровне use case (проверка на уровне доменной сущности или БД)
- Применимо только для полей типа `select_one` и `select_all` — для остальных типов вызов приведёт к логической ошибке (защита на уровне роутера)
- Нельзя добавить enum в **удалённое** поле — проверка выполняется в роутере при загрузке поля
