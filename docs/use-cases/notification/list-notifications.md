# UseCase: ListNotifications — Список уведомлений

## Что решает

Возвращает список in-app уведомлений для текущего пользователя. Уведомления генерируются системой автоматически при назначении лида, создании задачи, приближении дедлайна и т.д. Доставляются через SSE (Server-Sent Events).

**Статус:** ❌ Не реализовано (планируется — Приоритет 3)

---

## Участники

| Поле | Значение |
|------|----------|
| **Actor** | Текущий авторизованный пользователь |
| **Роли** | Все роли |

---

## Входные данные

| Поле | Тип | Описание |
|------|-----|----------|
| `is_read` | `bool \| None` | Фильтр: только непрочитанные |
| `page` | `int` | Страница |
| `size` | `int` | Размер страницы |

---

## Типы уведомлений

| Тип | Когда генерируется |
|-----|--------------------|
| `lead_assigned` | При `AssignLead` — для нового назначенного |
| `task_created` | При `CreateTask` — для исполнителя задачи |
| `task_due_soon` | За N часов до дедлайна задачи |
| `task_overdue` | Дедлайн задачи прошёл |
| `lead_commented` | При `CreateLeadComment` — для назначенного менеджера |

---

## Порядок действий

```
1. Открыть Unit of Work
2. Загрузить уведомления пользователя (actor.id) с фильтрами и пагинацией
3. Вернуть PageResult[NotificationViewDTO]
```

---

## Результат (`NotificationViewDTO`)

| Поле | Тип |
|------|-----|
| `id` | `UUID` |
| `type` | `str` |
| `payload` | `dict` (контекст: lead_id, task_id и т.д.) |
| `is_read` | `bool` |
| `created_at` | `datetime` |

---

## Бизнес-правила

- Пользователь видит **только свои** уведомления
- Доставка через **SSE** — клиент подписывается на `/api/v1/notifications/stream`
- Уведомления хранятся в БД и не удаляются автоматически (только in-app, без Telegram/Email в v1)
