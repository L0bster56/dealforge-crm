# UseCase: DeleteFunnel — Удалить воронку (soft delete)

## Что решает

Выполняет мягкое удаление воронки продаж — устанавливает `is_deleted = True`. Воронка скрывается из списков, но остаётся в БД. Лиды, привязанные к удалённой воронке, сохраняют свою историю.

**Файл:** `backend/src/backend/application/funnel/use_cases/delete_funnel.py`

**Статус:** ✅ Реализовано

---

## Участники

| Поле | Значение |
|------|----------|
| **Actor** | Менеджер или выше |
| **Роли** | `sales_manager`, `director`, `admin` |

---

## Входные данные

Воронка передаётся как атрибут use case (`self.funnel`) — загружается заранее через `GetFunnel`.

Команда не требует дополнительных параметров (вызов через `execute()` без аргументов).

---

## Порядок действий

```
1. Проверить права актора через CanDeleteFunnelPolicy
   │  Правило: роль должна быть sales_manager и выше
   └─ Если нет прав → ошибка PermissionError (до открытия UoW)

2. Открыть Unit of Work

3. Вызвать funnel.delete()
   └─ Устанавливает is_deleted = True на доменной сущности

4. Сохранить изменения через uow.funnels.update_funnel(self.funnel)

5. Зафиксировать транзакцию (commit)
```

---

## Возможные ошибки

| Ошибка | Условие |
|--------|---------|
| `PermissionError` | Роль актора — `consultant` |

---

## Результат

`None` — успешное выполнение без возвращаемого значения.

---

## Бизнес-правила

- Удаление — **мягкое** (soft delete): физически запись остаётся в БД
- Воронку можно восстановить через `funnel.restore()` (метод существует на доменной сущности, use case восстановления не реализован в v1)
- **Лиды в воронке** при удалении воронки не перемещаются и не архивируются — это ответственность бизнес-процесса, в v1 не обрабатывается
- Источники (`Source`), настроенные на удалённую воронку, продолжают работать технически — их нужно деактивировать отдельно
