# UseCase: ChangePassword — Изменить пароль

## Что решает

Позволяет авторизованному пользователю сменить собственный пароль. Требует подтверждения старого пароля (нельзя менять пароль "вслепую"). Проверяет сложность нового пароля и запрещает установку того же пароля, что был раньше.

**Файл:** `backend/src/backend/application/auth/use_cases/change_password.py`

**Статус:** ✅ Реализовано

---

## Участники

| Поле | Значение |
|------|----------|
| **Actor** | Текущий авторизованный пользователь (self) |
| **Роли** | Все роли |

---

## Входные данные (`ChangePasswordCommand`)

| Поле | Тип | Описание |
|------|-----|----------|
| `old_password` | `str` | Текущий пароль пользователя |
| `new_password` | `str` | Новый желаемый пароль |

---

## Порядок действий

```
1. Проверить новый пароль через PasswordSpecification
   (минимальная длина, наличие цифр/букв/спецсимволов)
   └─ Если не прошёл → ошибка WeakPasswordError (до открытия UoW, без запроса в БД)

2. Проверить, что новый пароль ≠ старому через PasswordDiffSpecification
   (сравнение открытых строк, до хеширования)
   └─ Если одинаковые → ошибка SamePasswordError

3. Открыть Unit of Work

4. Проверить старый пароль через Argon2 hasher
   (verify(old_password, user.password_hash))
   └─ Если неверный → ошибка InvalidPasswordError

5. Захешировать новый пароль через hasher.hash(new_password)

6. Вызвать user.change_password(new_password_hash)

7. Сохранить пользователя в БД

8. Зафиксировать транзакцию (commit)
```

> Шаги 1–2 выполняются **до открытия транзакции** — это оптимизация: если пароль слабый или совпадает, нет смысла открывать соединение с БД.

---

## Возможные ошибки

| Ошибка | Условие |
|--------|---------|
| `WeakPasswordError` | Новый пароль не соответствует требованиям сложности |
| `SamePasswordError` | Новый пароль совпадает со старым |
| `InvalidPasswordError` | Старый пароль введён неверно |

---

## Результат

`None` — успешное выполнение без возвращаемого значения.

---

## Бизнес-правила

- Проверка сложности выполняется через **Specification** паттерн (`PasswordSpecification`) — легко заменить требования без изменения use case
- Сравнение нового и старого пароля происходит **до хеширования** по открытым строкам, а не по хешу — это намеренно, чтобы Argon2 не считался дважды
- Администратор **не может сменить пароль другому пользователю** через этот use case (только через отдельный механизм "сброса пароля", не реализован в v1)
