# UseCase: LoginUser — Вход в систему

## Что решает

Аутентифицирует пользователя по логину и паролю. Возвращает пару JWT-токенов (access + refresh), которые используются для авторизации всех последующих запросов. Обновляет время последней активности пользователя.

**Файл:** `backend/src/backend/application/auth/use_cases/login_user.py`

**Статус:** ✅ Реализовано

---

## Участники

| Поле | Значение |
|------|----------|
| **Actor** | Любой пользователь (авторизация не требуется) |
| **Роли** | Все роли (включая неактивных — проверяется отдельно) |

---

## Входные данные (`LoginUserCommand`)

| Поле | Тип | Описание |
|------|-----|----------|
| `username` | `str` | Логин пользователя |
| `password` | `str` | Пароль в открытом виде |

---

## Порядок действий

```
1. Открыть Unit of Work (транзакция)
2. Найти пользователя в БД по username
   └─ Если не найден → ошибка AuthUserNotFoundError
3. Проверить пароль через Argon2 hasher (verify)
   └─ Если пароль неверный → ошибка InvalidPasswordError
4. Проверить флаг is_active пользователя
   └─ Если is_active = false → ошибка InActiveUserError
5. Сгенерировать access_token (JWT, TTL = 15 мин)
6. Сгенерировать refresh_token (JWT, TTL = 30 дней)
7. Вызвать user.interact() → обновить last_interaction = now()
8. Сохранить обновлённого пользователя в БД
9. Зафиксировать транзакцию (commit)
10. Вернуть LoginUserResult
```

---

## Возможные ошибки

| Ошибка | Условие |
|--------|---------|
| `AuthUserNotFoundError` | Пользователь с таким username не найден |
| `InvalidPasswordError` | Пароль не совпадает с хешем в БД |
| `InActiveUserError` | Пользователь деактивирован (`is_active = false`) |

> Ошибки `AuthUserNotFoundError` и `InvalidPasswordError` возвращают одинаковое сообщение `"invalid password or username"` — намеренно, чтобы не раскрывать информацию о существовании пользователя.

---

## Результат (`LoginUserResult`)

| Поле | Тип | Описание |
|------|-----|----------|
| `access_token` | `str` | JWT для авторизации запросов (15 мин) |
| `refresh_token` | `str` | JWT для обновления токенов (30 дней) |
| `token_type` | `str` | Тип токена (`"bearer"`) |

---

## Бизнес-правила

- Пароль **никогда не хранится в открытом виде** — сравнение только через `Argon2.verify()`
- Деактивированный пользователь не может войти в систему, даже с правильным паролем
- `last_interaction` обновляется при каждом успешном входе — используется для аналитики активности
