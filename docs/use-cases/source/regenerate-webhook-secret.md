# UseCase: RegenerateWebhookSecret — Пересоздать секретный токен webhook

## Что решает

Генерирует новый секретный токен для webhook-источника. Необходим при компрометации старого токена. Старый токен немедленно становится невалидным — внешние системы должны обновить его в своих настройках.

**Файл:** `backend/src/backend/application/source/use_cases/regenerate_webhook_secret.py`

**Статус:** ✅ Реализовано

## Входные данные

Источник передаётся как атрибут use case (`self.source`). Дополнительных параметров нет.

---

## Порядок действий

```
1. Проверить тип источника:
   Если source.source_type ≠ SourceType.webhook → ошибка NotWebhookSourceError

2. Вызвать source.regenerate_secret()
   └─ Генерирует новый случайный токен
   └─ Хеширует его и сохраняет как secret_hash в конфигурации
   └─ Возвращает открытый токен (единственный момент его доступности)

3. Открыть Unit of Work

4. Сохранить источник с новым хешем через uow.sources.update(self.source)

5. Зафиксировать транзакцию (commit)

6. Вернуть RegenerateWebhookSecretResult(secret_token=token)
```

---

## Возможные ошибки

| Ошибка | Условие |
|--------|---------|
| `NotWebhookSourceError` | Источник не является webhook-типом |

---

## Результат (`RegenerateWebhookSecretResult`)

| Поле | Тип | Описание |
|------|-----|----------|
| `secret_token` | `str` | Новый секретный токен (показывается **один раз**) |

---

## Бизнес-правила

- Новый токен показывается **только один раз** — после этого в БД хранится только его хеш
- Старый токен **немедленно инвалидируется** — внешняя система должна обновить токен до следующего запроса
- Применяется только для webhook-источников — для public_form и manual этот use case не применим
