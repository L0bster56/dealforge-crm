# UseCase: MoveFunnelStage — Переместить этап воронки (drag-and-drop)

## Что решает

Изменяет позицию этапа в воронке продаж. Обеспечивает логику drag-and-drop: пользователь перетаскивает колонку Kanban-доски на новое место, и все остальные этапы автоматически сдвигаются.

**Файл:** `backend/src/backend/application/funnel/use_cases/move_funnel_stage.py`

**Статус:** ✅ Реализовано

## Входные данные (`MoveFunnelStageCommand`)

| Поле | Тип | Описание |
|------|-----|----------|
| `position` | `int` | Новая позиция этапа (0-based) |

Воронка и этап передаются как атрибуты use case (`self.funnel`, `self.stage`).

---

## Порядок действий

```
1. Открыть Unit of Work

2. Загрузить все этапы воронки из БД
   uow.stages.get_funnel_stages(self.funnel.id)

3. Переместить этап через FunnelStageOrderingServices.move(stages, self.stage, cmd.position)
   └─ Алгоритм:
      a) Отсортировать все этапы по текущему order
      b) Найти перемещаемый этап в списке
         └─ Если не найден → ошибка StageNotFunnelError
      c) Удалить этап из текущей позиции
      d) Вставить этап на новую позицию через insert(remaining, stage, new_position)
      e) Переназначить order = index для всего списка

4. Сохранить все обновлённые этапы через uow.stages.save_all(updated)

5. Зафиксировать транзакцию (commit)
```

---

## Возможные ошибки

| Ошибка | Условие |
|--------|---------|
| `StageNotFunnelError` | Перемещаемый этап не найден в списке этапов воронки |

---

## Результат

`None` — успешное выполнение без возвращаемого значения.

---

## Бизнес-правила

- Новая позиция **зажимается** в диапазон `[0, len(stages) - 1]` — нельзя переместить за границы списка
- Все этапы сохраняются атомарно в одной транзакции — нет риска рассогласования порядка
- После перемещения `order` у **всех** этапов обновляется (не только у перемещённого) — порядок всегда последовательный: 0, 1, 2, ...
