# UseCase: DeleteFunnelStage — Удалить этап воронки

## Что решает

Физически удаляет этап из воронки и автоматически пересчитывает порядок (`order`) оставшихся этапов. В отличие от воронки, этап удаляется **реально** из БД (не soft delete).

**Файл:** `backend/src/backend/application/funnel/use_cases/delete_funnel_stage.py`

**Статус:** ✅ Реализовано

---

## Участники

| Поле | Значение |
|------|----------|
| **Actor** | Менеджер или выше |
| **Роли** | `sales_manager`, `director`, `admin` |

---

## Входные данные

Воронка и этап передаются как атрибуты use case (`self.funnel`, `self.stage`). Дополнительных параметров нет.

---

## Порядок действий

```
1. Открыть Unit of Work

2. Загрузить все этапы воронки из БД
   uow.stages.get_funnel_stages(self.funnel.id)

3. Убрать удаляемый этап из списка и пересчитать порядок через
   FunnelStageOrderingServices.remove(stages, self.stage)
   └─ Алгоритм:
      a) Отфильтровать список — исключить удаляемый этап
      b) Нормализовать оставшиеся этапы (order = index)

4. Физически удалить этап из БД:
   uow.stages.delete_stage(self.stage)

5. Сохранить обновлённый порядок оставшихся этапов:
   uow.stages.save_all(updated_stages)

6. Зафиксировать транзакцию (commit)
```

`None` — успешное выполнение без возвращаемого значения.

---

## Бизнес-правила

- Удаление **реальное** (hard delete) — этап навсегда исчезает из БД
- После удаления оставшиеся этапы **получают новые последовательные `order`** (0, 1, 2, ...) — пробелов в нумерации нет
- Лиды, находившиеся в удалённом этапе, в текущей реализации **остаются без валидного `stage_id`** — это известная проблема, которую нужно решить при реализации Lead-домена (принудительный перенос лидов перед удалением этапа или проверка на наличие лидов)
