# UseCase: CreateUser — Создать пользователя

## Что решает

Создаёт нового пользователя системы. Только администратор может создавать пользователей. Use case обеспечивает уникальность email и username, проверяет сложность пароля и хеширует его перед сохранением.

**Файл:** `backend/src/backend/application/user/use_cases/create_user.py`

**Статус:** ✅ Реализовано

---

## Участники

| Поле | Значение |
|------|----------|
| **Actor** | Администратор системы |
| **Роли** | `admin` |

---

## Входные данные (`CreateUserCommand`)

| Поле | Тип | Описание |
|------|-----|----------|
| `first_name` | `str` | Имя пользователя |
| `last_name` | `str` | Фамилия пользователя |
| `username` | `str` | Логин (уникальный) |
| `email` | `str` | Email (уникальный) |
| `password` | `str` | Пароль в открытом виде |
| `role` | `UserRole` | Роль: `consultant / sales_manager / director / admin` |

---

## Порядок действий

```
1. Проверить права актора через CanCreateUserPolicy
   │  Правило: только admin может создавать пользователей
   └─ Если нет прав → ошибка PermissionError (до открытия UoW)

2. Открыть Unit of Work

3. Проверить уникальность email
   └─ Если email уже существует → ошибка EmailAlreadyExistsError

4. Проверить уникальность username
   └─ Если username уже существует → ошибка UsernameAlreadyExistsError

5. Проверить сложность пароля через PasswordSpecification
   └─ Если пароль слабый → ошибка WeakPasswordError

6. Захешировать пароль через Argon2 hasher

7. Создать доменную сущность User через фабричный метод User.create(...)
   (генерируется новый UUID, устанавливается is_active=True)

8. Сохранить пользователя в БД

9. Зафиксировать транзакцию (commit)

10. Вернуть CreateUserResult(user_id=...)
```

---

## Возможные ошибки

| Ошибка | Условие |
|--------|---------|
| `PermissionError` | Актор не является администратором |
| `EmailAlreadyExistsError` | Email уже используется другим пользователем |
| `UsernameAlreadyExistsError` | Username уже занят |
| `WeakPasswordError` | Пароль не соответствует требованиям сложности |

---

## Результат (`CreateUserResult`)

| Поле | Тип | Описание |
|------|-----|----------|
| `user_id` | `UUID` | ID созданного пользователя |

---

## Бизнес-правила

- Новый пользователь сразу создаётся с `is_active = True`
- Роль устанавливается администратором при создании — самостоятельная регистрация в системе недоступна (нет публичного `/register`)
- `CanCreateUserPolicy` дополнительно может ограничивать создание admin-пользователей (защита от эскалации привилегий)
