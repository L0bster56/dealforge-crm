# UseCase: GetUserById — Получить пользователя по ID

## Что решает

Возвращает данные конкретного пользователя по его UUID. Используется в административной панели для просмотра профиля сотрудника.

**Файл:** `backend/src/backend/application/user/use_cases/get_user_by_id.py`

**Статус:** ✅ Реализовано

---

## Участники

| Поле | Значение |
|------|----------|
| **Actor** | Любой авторизованный пользователь |
| **Роли** | Все роли (ограничения по ролям не установлены на уровне use case) |

---

## Входные данные (`GetUserByIdCommand`)

| Поле | Тип | Описание |
|------|-----|----------|
| `user_id` | `UUID` | Идентификатор искомого пользователя |

---

## Порядок действий

```
1. Открыть Unit of Work
2. Загрузить пользователя из БД по user_id
3. Если пользователь не найден → ошибка UserNotFoundError
4. Вернуть GetUserByIdResult с данными пользователя
```

---

## Возможные ошибки

| Ошибка | Условие |
|--------|---------|
| `UserNotFoundError` | Пользователь с указанным ID не существует в БД |

---

## Результат (`GetUserByIdResult`)

| Поле | Тип | Описание |
|------|-----|----------|
| `first_name` | `Name` | Имя |
| `last_name` | `Name` | Фамилия |
| `username` | `Username` | Логин |
| `email` | `Email` | Email |
| `last_interaction` | `datetime \| None` | Время последней активности |
| `is_active` | `bool` | Активен ли пользователь |
| `role` | `UserRole` | Роль пользователя |

---

## Бизнес-правила

- `password_hash` **не возвращается** — только публичные данные
- Деактивированные пользователи (`is_active = false`) возвращаются нормально — use case не фильтрует их
